最近後台問得最多的問題之一：能不能把 AI 學習助理直接拉進微信、QQ 裡，讓它 24 小時線上陪學？

DeepTutor 的學習夥伴（Partner）就是幹這個的。它同時活在網頁介面和外部聊天應用裡，個人微信掃描 QR Code 登入就能用，Telegram 拿個 token 就能跑，總共 16 個管道隨便挑。

但是問題來了。管道這麼多怎麼選？設定流程怎麼走？多個人共用同一個夥伴，聊天記錄會不會互相看到？

這一頁就是官方的維運指南，接下來我們把訊息流轉、新舊方案區別、設定流程和全部管道入口，一次講清楚。

Partners 是可以同時存在於網頁介面和外部即時通訊（IM）應用裡的持久 DeepTutor 夥伴。它不是第二套 bot engine。每條入站訊息都會變成一個作用域在該 Partner 下的普通 chat-agent turn：

IM / Web message -> PartnerRunner -> ChatOrchestrator -> AgenticChatPipeline -> tools -> reply

就是沒有另起爐灶：你在網頁裡怎麼聊，在微信裡就怎麼聊，背後是同一套管線，真能跑。

本頁是維運指南。想了解夥伴是什麼（它的靈魂、資料庫、記憶與網頁 Chat 檢視），見探索 → 夥伴。夥伴也可以在一輪普通聊天裡透過我的智慧代理被諮詢。

和舊 TutorBot 的區別

舊 TutorBot 新 Partner
獨立 bot engine，工作區在 data/tutorbot// 複用 Chat loop，作用域在 data/partners//workspace/
deeptutor bot ... 命令 deeptutor partner list/create/start/stop
手寫 bot YAML 裡的 channels Partners UI 中按 schema 渲染的 channel cards
bot skills / memory 獨立處理 分配的 KB、skills、notebooks、tools、memory 像普通 chat context 一樣掛載

如果你當初也用過舊的 TutorBot，那這波升級可以說是脫胎換骨：不用再手寫 bot YAML，所有東西都在介面裡點兩下就能配好。

舊 /tutorbot/* 文件地址會重新導向到對應的 /partners/* 頁面，已有外鏈和書籤仍可繼續使用。

所有權、分配與私有會話

任何已認證使用者都可以建立 Partner，並自動成為其所有者。所有者和管理員可以管理它的靈魂設定、資料庫、管道、模型、生命週期與刪除操作。管理員還可以把 Partner 分配給其他使用者；被分配的使用者可以與它對話，但只能看到身份卡片，看不到設定和憑據。

Partner 的設定與複製進來的資料庫是共享的，關係狀態則彼此隔離。每個已認證的非管理員使用者都在 users/<user_id>/ 下擁有自己的會話檔案和關係記憶。與該使用者互動時，Partner 還可以讀取這個使用者自己的共享記憶；新學到的偏好只寫入這段私有的夥伴—使用者關係記憶。因此，兩個人使用同一個 Partner 時不會看到彼此的會話或已學習偏好。

管理員會話和未歸屬到帳號的管道訊息則相容性地使用 Partner 頂層的會話與記憶作用域。

隱私這塊的設計相當到位：兩個人用同一個夥伴也不會串台，這點必須按讚。

推薦設定流程

  1. 在 Partners -> New partner 建立 Partner。
  2. 啟用任何 channel 前，先填好 Identity 和 Soul 。第一條 IM 回覆就會使用這個 soul。
  3. 在 Mind 裡選擇模型；測試階段先少開可選工具。
  4. 在 Library 裡先分配一個小 KB 或 skill。資源會複製進 Partner workspace。
  5. 在 Channels 裡先只啟用一個 channel，並從本機/私有測試開始。
  6. 除錯時保留 send_progress 和 send_tool_hints ，生產環境再按需要關閉。
  7. 對真實使用者開放前，把 allow_from: ["*"] 換成明確 sender ids。

Partner Groups（夥伴群組）

Partners 頁面還支援一等公民的 Partner Groups（夥伴群組）。從兩個或更多 Partner 組建群組，選擇成員、討論模式和共享記憶模式，就能在同一場討論中保留每個 Partner 各自的角色與推理方式。

每個群組都有獨立的會話與持久歷史。一輪訊息可以發給全部成員，也可以只指定部分成員；每個成員的回覆佔據獨立 seat。某個 seat 失敗時，可以只重試這一席，而不用讓已經答完的 Partner 全部重跑。

簡單說，就是拉一群 AI 開圓桌：每個席次獨立發言，誰翻車了還能單獨重試，不用全員重來，這玩法確實有點上頭。

執行環境狀態

data/partners/<partner_id>/
├── config.yaml                  # Partner identity, model, channels, tools
├── sessions/                    # 共享/未归属账号的会话
│   ├── <session_key>.jsonl      # 每个会话一个 append-only 文件
│   └── _index.json              # 需要时创建的归档元数据
├── channels/
│   └── <channel>/...            # QR token、cursor、conversation ref
├── users/<user_id>/             # 已认证用户的私有关系状态
│   ├── sessions/<session_key>.jsonl
│   └── workspace/memory/
└── workspace/
    ├── knowledge_bases/         # 复制过来的 assigned KBs
    └── user/
        ├── workspace/SOUL.md
        ├── workspace/skills/<name>/SKILL.md
        ├── workspace/notebook/
        └── workspace/memory/

分配資源會複製進 Partner 工作區，這是刻意設計：即使原使用者工作區後續變化，夥伴仍保留一份穩定的資料庫。

對話命令

所有 Partner 對話介面共用一組簡短的斜線命令：

  • /help —— 檢視可用命令。
  • /new —— 封存當前會話並新開一段； /branch 會封存當前會話，再從其副本繼續。
  • /sessions —— 列出會話 id； /resume <session-id> 還原已封存會話， /delete <session-id> 永久刪除會話。
  • /status —— 檢視 Partner、會話、模型與工具狀態； /history [n] 檢視最近訊息。
  • /tool [on|off <name>|reset] —— 檢視或調整 Partner 已啟用的工具。
  • /link <code> —— 在外部 IM 私聊裡，把該聊天帳號關聯到在 Web 應用中生成此 code 的已登入 DeepTutor 使用者。

網頁介面還是命令列工具

設定管道推薦用網頁介面，因為它會從 /api/v1/partners/channels/schema 渲染即時 schema，並自動對 secret 欄位遮罩顯示。命令列工具更適合生命週期檢查：

deeptutor partner list
deeptutor partner start math-tutor
deeptutor partner stop math-tutor
