原文連結：https://docs.deeptutor.info/zh-cn/get-started/cli-only/

最近不少朋友在後台問我，DeepTutor 那一整套 Web 應用裝下來有點重，有沒有更輕的玩法。

還真有。DeepTutor 官方一共提供了 4 種安裝方式，今天要講的就是其中的選項 4：僅命令列工具（CLI）安裝。不開網頁介面，不問連接埠，直接從原始碼 checkout（原始碼目錄）裝，連 PyPI（Python 官方包儲存庫）都不用走。

把它扔到沒有圖形介面的伺服器、虛擬機器，或者塞進 Claude Code、Codex 這類智慧代理（Agent）的執行框架（harness）裡當工具用，都合適。

但是問題來了。裝得這麼輕，功能會不會偷工減料？哪些能用、哪些不能用？接下來，我們就一步一步把它裝明白，實測下來在伺服器上真能跑。

一、安裝

整套安裝一個程式碼塊搞定，前提是先裝好 Git（版本管理工具）：

git clone https://github.com/HKUDS/DeepTutor.git
cd DeepTutor

# 创建 venv（macOS / Linux）
# Windows PowerShell：
#   py -3.11 -m venv .venv-cli ; .\.venv-cli\Scripts\Activate.ps1
python3 -m venv .venv-cli && source .venv-cli/bin/activate
python -m pip install --upgrade pip

python -m pip install -e ./packaging/deeptutor-cli
deeptutor init --cli
deeptutor chat

逐行拆開看：git clone 從 GitHub（程式碼託管平台）把儲存庫拉到本機；註解裡的兩行是給 Windows PowerShell 使用者的寫法，macOS / Linux 用下面這行建立並啟用 Python 虛擬環境（venv）；pip install --upgrade pip 先把 pip（Python 套件管理器）升到最新；python -m pip install -e ./packaging/deeptutor-cli 才是真正裝包的一步；deeptutor init --cli 做初始化；deeptutor chat 直接進入對話。

兩個細節要注意。

第一，僅 CLI 的包是從原始碼 checkout 安裝的，不走 PyPI。這種可編輯安裝（editable install）本質是指向你本機這份原始碼，所以 clone 下來的目錄別刪。

第二，deeptutor init --cli 和完整版應用共享同一份 data/user/settings/ 目錄結構，但流程有幾點不一樣：

  • 跳過 後端 / 前端連接埠的詢問
  • 向量化模型（Embedding）選擇器預設選當前服務商，否則選 OpenAI（不需要 deeptutor kb … 或 RAG（檢索增強生成）工具時按 s 跳過）
  • 網頁搜尋仍是可選項，不需要 Web Search 時可跳過服務商（Provider）選擇器
  • 除核心設定外，還會寫入 document_parsing.json 、 pageindex.json 、 ima.json 、 llamaindex.json 、 graphrag.json 和 lightrag.json
  • 仍然會詢問當前啟用的大語言模型（LLM）提供商和模型

二、什麼場景用它

  • 把 DeepTutor 當作工具，掛在另一個 agent 的 harness 裡跑（Claude Code、Codex、OpenCode 等）
  • 沒有瀏覽器的無頭（headless）伺服器 / VM
  • 想要不帶 Node.js 工具鏈的快速安裝

三、常用命令

deeptutor chat                                          # 交互式 REPL
deeptutor chat --capability deep_solve --tool rag --kb my-kb
deeptutor run chat "解释一下傅里叶变换"
deeptutor run deep_solve "解 x^2 = 4" --tool rag --kb my-kb
deeptutor kb create my-kb --doc textbook.pdf
deeptutor memory show
deeptutor config show

第一行進入互動式對話環境（REPL）；第二、三行是單次執行，還能掛上 RAG 工具和知識庫一起跑；後面三條分別用來建知識庫、看記憶、看設定。

完整命令面：DeepTutor CLI。

四、哪些能用、哪些不能

本機 deeptutor-cli 安裝不含任何 Web 資源或伺服器依賴。請保留原始碼 checkout（原始碼目錄），可編輯安裝是指向它的。

很多人看到這裡，基本就放棄了：功能是不是被砍了一半？

直接上官方對比表，一目瞭然：

功能 僅 CLI 完整安裝
deeptutor chat 互動式 REPL ✅ ✅
deeptutor run capabilities ✅ ✅
deeptutor kb （知識庫） ✅ （init 時選擇啟用） ✅
deeptutor notebook ✅ ✅
deeptutor memory ✅ ✅
deeptutor partner （Partners） ✅ （補裝 channel SDK 後，見下文） ✅
deeptutor config show ✅ ✅
deeptutor provider login ✅ ✅
遠端 MCP client ✅ （core；無需 Partner SDK extra） ✅
deeptutor serve （FastAPI） ❌ ✅
deeptutor start （Web UI） ❌ ✅
Co-Writer UI ❌ ✅
Memory Workbench UI ❌ ✅
互動式書本 UI ❌ ✅

後續要加 Web 應用，裝 PyPI 包（選項 1），然後在同一工作區跑 deeptutor init + deeptutor start 即可，互不衝突。

五、補裝 Partner channel SDK

僅 CLI 安裝也可以執行 deeptutor partner，但管道的開發工具包（SDK）不會預設安裝。本機的 deeptutor-cli 專案沒有定義任何可選元件（extras），請改用儲存庫裡的 requirements 鏡像檔案來裝 SDK 全集（原始碼 checkout 本來就在手邊）：

python -m pip install -r requirements/partners.txt

這一條會覆蓋全部內建管道 SDK（wecom-aibot-sdk、qq-botpy、slack-sdk、lark-oapi、python-telegram-bot、dingtalk-stream 等）。

Matrix 管道單獨打包：pip install -r requirements/matrix.txt，要加密房間再裝 requirements/matrix-e2e.txt（需要系統級 libolm 庫）。

注意這不會安裝網頁介面；Partner 設定仍寫入當前工作區的 data/partners/<id>/ 和 data/user/settings/。

六、讓另一個 agent 來呼叫

CLI 是 agent-native 的。deeptutor run --format json 每行輸出一個 JSON 事件，kb list、kb search、session show、notebook show 等資料查詢命令在已實現的地方都暴露 JSON，方便接到另一個 agent 的執行框架（harness）裡。

把專案根目錄的 SKILL.md 丟給任何會調工具的大語言模型，它就能自己驅動 DeepTutor。具體模式見 Agent handoff。

七、升級

cd DeepTutor
git pull
pip install -e ./packaging/deeptutor-cli --upgrade

先拉最新程式碼，再原地升級，三行命令的事，工作區資料不受影響。

八、常見錯誤

裝完之後 deeptutor: command not found

console script 沒裝到 PATH 上。確認 venv 已啟用，或直接呼叫：

python -m deeptutor_cli.main chat

跑 deeptutor serve 時報 ModuleNotFoundError: No module named 'fastapi'

deeptutor serve 在僅 CLI 安裝裡不可用，這不是故障。請用 PyPI 或 從原始碼安裝 的完整版。

Partner 管道命令提示 SDK 缺失

管道 SDK（wecom-aibot-sdk、qq-botpy、slack-sdk、lark-oapi 等）隨 requirements 鏡像檔案分發，不在僅 CLI 包裡：

python -m pip install -r requirements/partners.txt
