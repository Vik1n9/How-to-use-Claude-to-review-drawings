最近總有朋友問我，DeepTutor 能不能別在宿主機上裝一堆 Python、Node 依賴，給伺服器留個乾淨的環境。

可以，而且方式相當優雅：這就是 DeepTutor 的選項 3，用 Docker（容器部署工具）一個容器跑起完整 Web 應用，映像檔直接從 GitHub Container Registry（GitHub 官方容器映像檔儲存庫）拉取。前後端、資料卷全給你安排好，連接埠 3782 開啟瀏覽器就能用。

但是問題來了。容器跑起來只是第一步，連接埠怎麼對映、資料怎麼持久化、怎麼連宿主機上的本機模型？接下來，我們就把這些一次講清楚。

一、拉映像檔並執行

映像檔在 GitHub Container Registry 上，兩個 tag 先記一下：

  • ghcr.io/hkuds/deeptutor:latest —— 當前穩定版
  • ghcr.io/hkuds/deeptutor:<version> —— 精確版本；預發布只發版本 tag，不更新 latest

一條命令跑起來：

docker run --rm --name deeptutor \
  -p 127.0.0.1:3782:3782 \
  -v deeptutor-data:/app/data \
  ghcr.io/hkuds/deeptutor:latest

只需要對映 3782。 瀏覽器只跟前端 origin 通訊；容器裡的 Next.js 中介軟體（web/proxy.ts）會把每個 /api/* 和 /ws/* 請求在容器內部轉發給 FastAPI 後端，所以為了讓 UI 正常工作，你不需要把 8001 暴露到宿主機。對映它（-p 127.0.0.1:8001:8001）是可選的，只在你想用 curl 或指令碼直接調 API 時才有用。

開啟 http://127.0.0.1:3782 就能看到介面。

容器首次啟動時會建立 /app/data/user/settings/*.json；從 Web 的設定頁面裡設定模型服務商即可。設定、API 金鑰（API key）、日誌、工作區檔案、記憶、知識庫、Partner 工作區（data/partners/<id>/）全部持久化在 deeptutor-data 這個資料卷（volume）裡。

還有個省心的設計：可選依賴宣告在部署上，別鑽進容器裡手動裝：設好 DEEPTUTOR_EXTRAS（系統庫用 DEEPTUTOR_APT_PACKAGES），每個容器啟動時自動補齊，這一手是真香。

二、後台模式

加 -d 讓它在後台跑：

docker run -d --name deeptutor \
  -p 127.0.0.1:3782:3782 \
  -v deeptutor-data:/app/data \
  ghcr.io/hkuds/deeptutor:latest

docker logs -f deeptutor      # 跟踪日志
docker stop deeptutor         # 停止
docker rm deeptutor           # 删除（volume 仍保留）

deeptutor-data 資料卷會在 stop / rm 之間保留設定和工作區。如果真要從頭來：docker volume rm deeptutor-data。

三、遠端 Docker / 反向代理

瀏覽器始終只跟前端 origin（:3782）通訊；容器裡的 Next.js 中介軟體會在伺服器端把 /api/* 和 /ws/* 轉發給 localhost:8001 上的後端。

所以常見的單容器場景下，你完全不需要設定任何 API base，把反向代理 / TLS 終止器指向發布出來的 :3782 即可：

deeptutor.example.com {
    reverse_proxy localhost:3782
}

更有意思的是，連 API base 都不用配。只有拆分部署（後端跑在另一個容器或主機上）才需要設定：在掛載資料卷裡的 data/user/settings/system.json 中，把它設成前端伺服器用來訪問後端的內部網路地址，這個值由代理在伺服器端讀取，不會發給瀏覽器：

{
  "next_public_api_base": "http://backend:8001"
}

next_public_api_base_external（及其別名 public_api_base）作為更低優先順序的回退被接受，儲存時會歸一化。

跨域（CORS）只在開啟認證且前端跨 origin 時才有意義：cors_origins 列出哪些前端頁面 origin 可以呼叫後端。未開啟認證時，DeepTutor 預設允許正常 HTTP/HTTPS 瀏覽器 origin。

{
  "cors_origins": ["https://deeptutor.example.com"]
}

四、改宿主機連接埠

改 -p host:container 對映的左邊即可：

docker run --rm --name deeptutor \
  -p 127.0.0.1:8088:3782 \
  -v deeptutor-data:/app/data \
  ghcr.io/hkuds/deeptutor:latest

如果還想把 API 暴露到宿主機，再加 -p 127.0.0.1:8089:8001。如果你在 /app/data/user/settings/system.json 裡改了容器側連接埠，重新啟動並把每條對映右側同步改掉。

五、連本機 LLM（Ollama / LM Studio / llama.cpp / vLLM）

Docker 裡的 localhost 指的是容器本身，不是宿主機，這一點坑過不少人。

要訪問宿主機上跑的模型服務，用 host gateway：

docker run --rm --name deeptutor \
  -p 127.0.0.1:3782:3782 \
  --add-host=host.docker.internal:host-gateway \
  -v deeptutor-data:/app/data \
  ghcr.io/hkuds/deeptutor:latest

然後在 設定 → LLM（或 Embedding）裡，把服務商 Base URL 指到 host.docker.internal：

服務 Base URL
Ollama LLM http://host.docker.internal:11434/v1
Ollama embedding http://host.docker.internal:11434/api/embed
LM Studio http://host.docker.internal:1234/v1
llama.cpp http://host.docker.internal:8080/v1

Docker Desktop（macOS / Windows）通常不需要 --add-host 就能解析 host.docker.internal。Linux 上，這個 flag 是在現代 Docker Engine 上建立這個 hostname 的可移植方式。

Linux 替代方案 —— host networking

加 --network=host，去掉 -p 引數：

docker run --rm --name deeptutor \
  --network=host \
  -v deeptutor-data:/app/data \
  ghcr.io/hkuds/deeptutor:latest

容器直接共享宿主機網路，所以開啟 http://127.0.0.1:3782（或 system.json 裡的 frontend_port），宿主機服務也能用普通的 localhost 地址訪問，比如 http://127.0.0.1:11434/v1。

Host networking 把容器連接埠直接暴露在宿主機上，可能跟已有服務衝突。

六、升級

docker pull ghcr.io/hkuds/deeptutor:latest
docker rm -f deeptutor 2>/dev/null
docker run --rm --name deeptutor \
  -p 127.0.0.1:3782:3782 \
  -v deeptutor-data:/app/data \
  ghcr.io/hkuds/deeptutor:latest

資料卷會保留，你的設定、知識庫、記憶都能撐過升級。

設定 → 關於 會識別 Docker 映像檔並檢查是否有新版本，但替換容器仍屬於部署操作：按上面的步驟拉取新映像檔並重建容器。DeepTutor 不會在執行中的容器裡原地升級包。

七、常見錯誤

Bind for 0.0.0.0:3782 failed: port is already allocated

lsof -i :3782          # macOS
ss -ltnp | grep :3782  # Linux

幹掉衝突的處理程序，或者在 -p 對映裡換一個宿主機連接埠。

容器立刻退出

docker logs deeptutor | tail -30

無效的 LLM 憑據會被捕獲並記為 warning，不會讓後端啟動失敗。如果容器已經退出，請從日誌中尋找其他致命錯誤。Web UI 可用後，到 設定 → Models 修正憑據即可。

前端能載入但 API 呼叫失敗（拆分部署）

用單容器映像檔時不該出現這種情況，容器內的代理會自動把 /api/* 轉發給後端。如果你跑的是拆分部署（後端在另一個容器或主機上），在資料卷裡的 data/user/settings/system.json 把 next_public_api_base 設成前端伺服器訪問後端用的內部網路地址，然後重新啟動。

Docker 裡的多使用者模式

直接在資料卷的 data/user/settings/auth.json 裡把認證開關開啟（"enabled": true），然後重新啟動。容器會自動生效。完整設定見 多使用者部署。
