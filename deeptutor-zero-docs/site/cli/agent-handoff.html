最近不少朋友在後台問我：DeepTutor 裝好了，難道以後每一步都得自己手動敲命令？

真不用。

DeepTutor 的命令列工具（CLI）從設計之初，就是為了被其他智慧代理（Agent）驅動的：回合（turn）執行可以輸出結構化 JSON，會話（session）能跨行程還原，所有受支援的入口都集中在一個技能檔案裡，任何會用工具的大語言模型（LLM）讀完就能直接上手。

這份技能檔案，就是儲存庫根目錄那份只有 203 行的 SKILL.md。

把它丟給 Claude Code、Codex、OpenCode、Hermes 這 4 類主流環境，它們就能替你驅動整個 DeepTutor，等於免費獲得一支隨叫隨到的 AI 學習助手團隊。

但是問題來了。不同 Agent 的接法並不一樣，會話怎麼串、JSON 怎麼解析，裡面全有講究。

接下來這一頁，就是那套完整的交接打法，我按環境逐個給大家演示。

基本套路

先把醜話說在前面。

根目錄的 SKILL.md 是一份精簡交接文件，不是窮盡一切的契約：它的列表裡就沒列 ask_questions、immersive_reading、course_study、immersive_watching。

想即時查能力（capability），用 plugin list / --help；想看 JSON 結構，查本頁就行。

還有一點要注意，--tool 只影響使用者手動開關；rag、code_execution 這類要滿足條件才會自動掛載。

把 SKILL.md 丟給你選定的 Agent，它就能做到這五件事：

  • 跑各種能力（deep_solve、deep_research、deep_question、……）
  • 管理知識庫（kb create、kb search、kb add）
  • 用 --session 跑長程多輪會話
  • 把 JSON 輸出透過管線交給下游工具
  • 在一個任務中途切換能力和工具

Claude Code

Claude Code 的接法最省心：只要專案根目錄有 SKILL.md，它就會自動讀取。

cd /your-project
# DeepTutor 的 SKILL.md 在 DeepTutor/SKILL.md；复制或软链过来：
ln -s /path/to/DeepTutor/SKILL.md ./SKILL.md

# 或者更简单：通过 Claude Code 的 allowed-skills 配置带进来

一旦 Claude Code 看到 SKILL.md，它就理解這套命令列工具了，你可以直接用自然語言提示：

> 给我做一个未来两周关于线性代数的学习计划。用 DeepTutor：
> 从 ./textbooks/ 里的 PDF 创建一个 KB，然后出 10 道测验题，
> 分布在三个难度上。

Claude Code 會把它翻譯成：

deeptutor kb create linalg --docs-dir ./textbooks/

# 第一次出题 —— 开一个新 session，从 'done' 事件里抓 session id，
# 后两轮复用它。
SESSION_ID=$(deeptutor run deep_question "Linear algebra fundamentals" \
  --kb linalg \
  --config num_questions=4 --config difficulty=easy \
  --format json | jq -r 'select(.type=="done") | .session_id')

deeptutor run deep_question "Linear algebra eigenvectors" \
  --kb linalg --session "$SESSION_ID" \
  --config num_questions=3 --config difficulty=medium

deeptutor run deep_question "Linear algebra advanced theorems" \
  --kb linalg --session "$SESSION_ID" \
  --config num_questions=3 --config difficulty=hard

注意看，它用 --session 把三輪出題串在了一起，上下文一點沒丟。

把 deeptutor 命令列接成 Claude Code 的子智慧代理

如果你想在 Claude Code 裡固定養一個「學習智慧代理」，讓它永遠走 deeptutor：

name: study-agent
description: Use this agent for any learning, study planning, or quiz generation task. It drives DeepTutor.
tools: [Bash, Read, Write]
system_prompt: |
  You are a study planner. You have access to the `deeptutor` CLI via the Bash tool.
  Read SKILL.md before doing anything else. Then build study plans, generate quizzes,
  and run research turns by calling `deeptutor run <capability> "..."` with the right
  flags. Always pass `--format json` for parsing.

Codex（OpenAI Codex CLI）

Codex 走類似的套路：把 SKILL.md 放到專案根目錄，然後提示：

codex "Read SKILL.md, then run a deep research turn on transformer attention mechanisms. Use the 'papers' knowledge base if it exists; if not, just web search."

對於走 OAuth（開放授權登入）的服務商（Provider）（比如 OpenAI Codex 自己），DeepTutor 內建了登入命令：

deeptutor provider login openai-codex
# 浏览器打开做 OAuth，token 存到工作区

之後就可以用拿到的權杖，透過 DeepTutor 使用 OpenAI Codex。

OpenCode

OpenCode 也是同樣的玩法，把專案的 SKILL.md 加進來：

opencode init
ln -s /path/to/DeepTutor/SKILL.md ./SKILL.md
opencode "Plan a study session on quantum mechanics using deeptutor"

Hermes / 通用 Agent 框架

對於原生不認 SKILL.md 的 Agent 框架（LangChain Agent、AutoGen、自訂迴圈），把 deeptutor 包成一個工具定義就行。

一個最小化的 LangChain 封裝：

from langchain.tools import Tool
import subprocess
import json

def deeptutor_run(args_json: str) -> str:
    args = json.loads(args_json)
    cmd = [
        "deeptutor", "run",
        args["capability"],
        args["message"],
        "--format", "json",
    ]
    for tool in args.get("tools", []):
        cmd.extend(["--tool", tool])
    for kb in args.get("knowledge_bases", []):
        cmd.extend(["--kb", kb])
    if args.get("session_id"):
        cmd.extend(["--session", args["session_id"]])
    for key, value in args.get("config", {}).items():
        cmd.extend(["--config", f"{key}={json.dumps(value)}"])

    result = subprocess.run(cmd, capture_output=True, text=True)
    return result.stdout

deeptutor_tool = Tool(
    name="deeptutor_run",
    description=(
        "Run a DeepTutor capability. Args: JSON object with "
        "{capability, message, tools, knowledge_bases, session_id, config}. "
        "Returns one JSON event per line."
    ),
    func=deeptutor_run,
)

接好之後，你的智慧代理主迴圈就能直接呼叫了。

會話交接玩法

這裡面最強的一種用法：讓 Agent 在同一個會話裡串起多次能力呼叫，讓每個新的回合都繼承前一個回合的上下文。

# Step 1 —— 研究
SESSION_ID=$(deeptutor run deep_research "Survey 2026 papers on RAG" \
  --tool web_search --kb papers \
  --config mode=report --config depth=standard \
  --format json | \
  jq -r 'select(.type=="done") | .session_id')

# Step 2 —— 总结（同一 session，不同 capability）
deeptutor run chat "Summarize the top three findings as bullet points" \
  --session "$SESSION_ID" --format json

# Step 3 —— 出题（同一 session）
deeptutor run deep_question "The findings from this session" \
  --session "$SESSION_ID" \
  --config num_questions=5 \
  --format json

每一步都會繼承：

  • 完整對話歷史
  • 相同的會話身份與對話分支

還有個細節，每次 run 都會傳送自己的選擇，省略引數（flag）就等於 tools=[]、knowledge_bases=[]、language="en"，會覆蓋會話偏好。

需要時重複傳 --tool、--kb、--language 就行；對話上下文仍然是有狀態的。

JSON 事件解析

--format json 按行解析；無頭模式下的 ask_user 暫停會自動收到空回覆。

一個最小的 Python 消費者：

import json
import subprocess

proc = subprocess.Popen(
    ["deeptutor", "run", "deep_solve", "Find d/dx [sin(x²)]",
     "--tool", "reason", "--format", "json"],
    stdout=subprocess.PIPE,
    text=True,
)

answer = ""
for line in proc.stdout:
    event = json.loads(line)
    if event["type"] == "result":
        answer = event.get("metadata", {}).get("response", "")
    elif event["type"] == "tool_call":
        print(f"→ Tool: {event['content']}({event['metadata']['args']})")
    elif event["type"] == "error":
        print(f"× Error: {event['content']}")
        break
    elif event["type"] == "done":
        session_id = event["session_id"]
        break

或者用 jq：

# 拿到最终答案
deeptutor run chat "Hello" --format json | \
  jq -r 'select(.type == "result") | .metadata.response // empty'

# 拿到 session id
deeptutor run chat "Hello" --format json | \
  jq -r 'select(.type=="done") | .session_id'

# 流式打印每个 stage 完成的瞬间
deeptutor run deep_research "..." \
  --config mode=report --config depth=quick \
  --format json | \
  jq -r 'select(.type=="stage_end") | "Stage finished: " + .stage'

你的 SKILL.md 裡到底放什麼

儲存庫內建的 SKILL.md 一共覆蓋五塊內容：

  1. When to Use —— 哪些使用者請求應該觸發 DeepTutor
  2. Prerequisites —— Python 3.11+、安裝方式、deeptutor init
  3. Commands —— Chat & Capabilities、Knowledge Bases、Partners、Skills、Books、Memory、Sessions、Notebooks、Providers、System
  4. REPL Slash Commands —— deeptutor chat 內部可用的命令
  5. Typical Workflows —— 一組智慧代理可以照著復刻的端對端 recipe

整份共 203 行，按「一次吞下去」的標準寫的，主流會用工具的模型（Claude Sonnet/Opus、GPT-4/5、Gemini Pro）讀一遍就能上手。

給雲端 Agent 準備的服務商權杖

DeepTutor 的本機命令列操作不需要瀏覽器，但模型 / 搜尋功能會去訪問你設定的服務商。

如果你的 Agent 跑在沙箱環境裡，先確認下面這些地址是可達的：

服務商（Provider） 需要放行的 API 位址（endpoint）
OpenAI api.openai.com:443
Anthropic api.anthropic.com:443
Google Gemini generativelanguage.googleapis.com:443
Azure OpenAI .openai.azure.com:443
本機 Ollama / vLLM data/user/settings/model_catalog.json 或行程環境變數裡設定的 API 位址

如果是 RAG（檢索增強生成）密集型工作流，還要放行你設定的搜尋服務商（Tavily、Brave、Jina、Serper、Perplexity、SearXNG 或 DuckDuckGo）。
