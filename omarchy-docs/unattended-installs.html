無人值守安裝

Omarchy ISO 可在無人鍵盤前時自行安裝。若安裝程式發現第二顆標記為 cidata 的磁碟帶有設定檔，即複製出來、略過設定精靈，裝完自行重開機。無需特製 ISO 或額外開機選單；沒接該磁碟則一切如常，進入一般精靈。

這讓 Omarchy 很適合作為拋棄式開發環境的基底映像：在 Proxmox 或用 Packer 建 VM，開機，走開，SSH 進去。cidata 即 cloud-init NoCloud 標籤，主流虛擬化工具皆知如何掛載。

The configuration files

檔案即安裝精靈所寫內容，最簡單的起手式是先跑一次互動安裝（例如 VM 內），再把 /root 所寫複製出來：

File / Required / Purpose user_configuration.json / Yes / Disk, hostname, timezone, keyboard user_credentials.json / Yes / Username and password hash user_full_name.txt / No / Git full name user_email_address.txt / No / Git email user_encrypt_installation.txt / No / true when the configuration carries a disk_encryption block authorized_keys / No / SSH public keys, one per line tailscale_authkey / No / Tailscale auth key for joining your tailnet on first boot

用 openssl passwd -6 "yourpassword" 產生 user_credentials.json 所需 password hash。

也可用空檔 defer-provisioning 取代 user_credentials.json，效果等同互動觸發的 prepare-for-another-owner 安裝：機器裝好不帶個人資料，首位開機者自選鍵盤並建帳號。適合 imaging rigs，磁碟不該帶任何人憑證。

SSH access

若有 authorized_keys，安裝會設為該使用者的 ~/.ssh/authorized_keys，啟用 sshd 並開防火牆。因 Omarchy 預設 openssh 服務停用、port 關閉，無人值守機器否則無法連入。安裝僅加入你的 keys，不放寬 SSH daemon 其他驗證設定。

若有 tailscale_authkey，機器首開即加入你的 tailnet：Tailscale 由 ISO 內建套件安裝，防火牆放行 tailnet interface，背景工作待有網路即執行加入並重試至成功。請用可重複使用、預授權的 key，一份映像可供多機。

Building the cidata drive

任何標籤正確的 filesystem 皆可，最簡單是小 ISO：

mkdir cidata cp user_configuration.json user_credentials.json authorized_keys cidata/ genisoimage -output cidata.iso -volid cidata -joliet -rock cidata/

再與 Omarchy ISO 一併掛給 VM，完整 Proxmox 範例：

qm create 101 --name my-omarchy \ --bios ovmf --machine q35 --cpu host --cores 4 --memory 8192 \ --ostype l26 --scsihw virtio-scsi-single \ --efidisk0 local-lvm:0,efitype=4m,pre-enrolled-keys=0 \ --scsi0 local-lvm:40,discard=on,iothread=1 \ --net0 virtio,bridge=vmbr0 --vga virtio --serial0 socket \ --ide2 local:iso/omarchy.iso,media=cdrom \ --ide3 local:iso/cidata.iso,media=cdrom \ --boot order='scsi0;ide2'

開機順序刻意磁碟在前：首次開機空碟會落到 ISO，之後即從碟上系統開機。

Two caveats

加密的無人值守安裝並非全無人：首次開機仍需有人輸入 LUKS passphrase。且 user_configuration.json 內的 disk_encryption block 以明文攜帶 passphrase，故由加密安裝產生的 cidata drive 視同機密保管。
