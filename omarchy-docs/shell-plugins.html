殼層外掛

Omarchy 桌面是以一個長期存活的 Quickshell 行程執行的，名稱叫做 omarchy-shell，螢幕上幾乎所有東西都是它裡面的外掛。狀態列是外掛，從狀態列垂下來的面板是外掛，表情符號挑選器與剪貼簿管理員這類全螢幕浮層是外掛，Omarchy 選單本身、鎖定畫面、polkit 授權對話框是外掛，連監看電池與深夜暖屏的無介面服務也是外掛。

這不只是實作細節。它代表你可以關掉桌面的零件、換掉它們，或自己寫一個，全程不必碰 Omarchy 的原始碼一行。

官方第一方外掛隨 Omarchy 出貨，住在 $OMARCHY_PATH/shell/plugins/。你自己加的，不論是實驗作品或從 GitHub 撿來的，都住在 ~/.config/omarchy/plugins/。兩者在啟動時以相同方式被發現，差別只在放在磁碟的哪裡。

查看手上有的外掛

omarchy plugin list

這會印出每個被發現的外掛，包含 id、是否啟用、第一方或第三方、種類（kind）與顯示名稱。餵給其他程式時可以加上 --json。

外掛 id 帶有命名空間。內建一律以 omarchy. 開頭，例如 omarchy.clock、omarchy.network、omarchy.notifications，這個命名空間是保留的，第三方外掛永遠不能占用。

開關外掛

omarchy plugin enable omarchy.tailscale omarchy plugin disable omarchy.weather

或用選單：Setup > Plugins 裡有 Enable、Disable、Add、Clone、Remove，每個動作只列出對該動作有意義的外掛供你挑。

啟用狀態存在 ~/.config/omarchy/shell.json，兩種外掛的規則略有不同。第三方外掛在該檔案出現其 id 才算啟用，不論是狀態列版面項目、plugins[] 裡的項目或 bar.id。第一方外掛裡非狀態列小工具則相反：預設全開，只有列進 disabledPlugins[] 才關掉。

完整的狀態列（bar）外掛沒有關閉狀態。狀態列永遠恰好有一個，所以你要換掉它，只能啟用另一個。狀態列小工具的擺放另見狀態列說明。

從 git 新增外掛

第三方外掛就是一個根目錄帶有 manifest.json 的 git 倉庫。

omarchy plugin add https://github.com/acme/omarchy-weather.git --enable

動手前，它會明白告訴你：外掛是以任意、無沙盒的程式碼，跑在你長期存活的殼層行程裡，並顯示網址請你確認。請認真看待。外掛不是設定檔，它是跟著你的工作階段一直跑的程式，權限等同你的使用者帳號。只加你願意執行的倉庫，啟用前先讀過程式碼。

接著它會把倉庫複製到暫存目錄，驗證 manifest，若已有外掛占用相同 id 就拒絕安裝，再搬進 ~/.config/omarchy/plugins/<id>/。沒加 --enable 時它會問你要不要現在啟用，你可以先說不要，讀完程式碼再說。它絕不會執行外掛裡的任何東西，不跑安裝鉤子，也不會要求 sudo，只複製檔案、檢查 manifest，再透過 IPC 翻一個開關。

更新就是對同一份 checkout 做 fast-forward pull：

omarchy plugin update acme.weather omarchy plugin update

不給 id 就更新全部由 git 管理的外掛。套用前會先給你看 diff，若你有它無法 fast-forward 越過的本機修改就拒絕更新，新版驗證失敗則 rollback。

omarchy plugin remove acme.weather

移除會先停用外掛。如果是 git checkout 就刪除（原始倉庫還在上游），如果是 symlink 就解除連結。手工建的、沒有 git 倉庫的外掛資料夾，會被搬到外掛目錄內的時間戳備份，而不是直接刪除。

複製內建外掛來改

這是我最喜歡的部分。想改內建小工具的行為，不要去編 $OMARCHY_PATH 底下的檔案，那些屬於套件，下次更新會被覆寫。把它複製出來：

omarchy plugin clone omarchy.clock

這會把整個外掛複製到 ~/.config/omarchy/plugins/dhh.clock（用你的使用者名稱，不是我的），重新命名為「My Clock」，啟用它，並把殼層從內建版切到你的複製品，原本狀態列小工具的位置與設定會保留。加上 --edit 會立刻用 $EDITOR 打開新目錄，選單裡的 Setup > Plugins > Clone Plugin 做的就是這件事。

使用者名稱前綴讓複製品的 id 屬於你，分享出去不會跟別人的撞到。對原本內建 id 的呼叫會被轉送到你的複製品，所以原本參照 omarchy.clock 的地方都不用改。玩壞了就用 omarchy plugin remove dhh.clock 把內建版換回來。

~/.config/omarchy/plugins/ 底下任何檔案一存檔，外掛程式碼就會自動重載，所以你可以開著編輯器，看著修改即時生效。

自己寫一個

外掛就是一個帶有 manifest.json 與若干 QML 的目錄。manifest 宣告 schemaVersion: 1、id、name、version、一個或多個 kind，以及 entryPoints 物件，為每種 kind 指向 QML 檔：

種類是什麼bar-widget 現行狀態列可放入分區的元件panel 常駐或召喚的浮動視窗overlay 全螢幕浮層menu 召喚出的選單介面service 無介面的常駐單例bar 取代內建的完整狀態列

一個外掛可以同時宣告多種 kind，比方說媒體外掛同時是 service 與 bar-widget。狀態列小工具會多一個 barWidget 區塊，包含顯示名稱、分類、可選的 defaultSection，以及 allowMultiple（說明狀態列上放多個合不合理）。多數小工具設為 false，間隔器與指示器設為 true。

發布前先檢查：

omarchy plugin validate ./my-plugin

這會跑跟殼層載入時相同的檢查：schema 版本、必填欄位、id 未占用保留空間、進入點是安全且確實存在的相對路徑、每種宣告的 kind 都有進入點、資料夾裡沒有 symlink。

完整說明以原始碼為準：Omarchy 倉庫的 shell/README.md 講 manifest 結構、殼層 IPC 契約與 shell.json 的確切形狀，shell/plugins/README.md 列出每個第一方外掛的 id、kind 與進入點。

分享給全世界

做出喜歡的東西後，把它放進公開 git 倉庫，發布機制就是這麼簡單，任何人對你的網址跑 omarchy plugin add，幾秒鐘就能跑起來。

想讓大家找得到，就去 omarchyplugins.com 登錄。那是 Omarchy 殼層外掛的社群目錄，動手寫之前先去逛逛，看看想做的東西是不是已經有人寫好了！
