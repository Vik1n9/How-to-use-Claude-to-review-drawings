最近幾篇把 PyPI 一鍵安裝和 Docker 容器部署都講過了，但總有一批朋友不滿足於此：想讀原始碼、想貢獻程式碼、想把 DeepTutor 改成自己的形狀。

這就是今天的選項 2：從原始碼安裝，適合基於原始碼目錄做開發，對貢獻者和高階使用者來說就是標配。環境要求兩行數字記好：Python 3.11–3.14 和 Node.js 22 LTS，與官方 CI 和 Docker 保持一致，不會出現文件一套、實際一套的錯位。

但是問題來了。原始碼安裝聽起來就勸退，裝完怎麼改、怎麼熱重載、那一堆可選元件又是什麼？接下來，我們一步步把它跑通。

一、安裝

先上主流程，Git（版本管理工具）克隆儲存庫，然後 pip（Python 套件管理器）可編輯安裝（editable install）加上前端依賴，一氣呵成：

git clone https://github.com/HKUDS/DeepTutor.git
cd DeepTutor

# 创建 venv（macOS / Linux）
# Windows PowerShell：
#   py -3.11 -m venv .venv ; .\.venv\Scripts\Activate.ps1
python3 -m venv .venv && source .venv/bin/activate
python -m pip install --upgrade pip

# 安装后端 + 前端依赖
python -m pip install -e .
( cd web && npm ci --legacy-peer-deps )

deeptutor init
deeptutor start --dev

拆開看：venv 那段是建立並啟用 Python 虛擬環境，Windows 使用者用註解裡的 PowerShell 寫法；python -m pip install -e . 把後端以可編輯模式裝進環境；括號那行進 web 目錄用 npm 裝前端依賴；deeptutor init 初始化設定；deeptutor start --dev 啟動。

deeptutor start 會為本機 web/ 前端建置一次生產版本並複用；--dev 則以熱重載（HMR）跑 Next.js。設定結構、連接埠、Ctrl+C 停止都和 PyPI 安裝 一致。

二、用 Conda 代替 venv

如果你當初跟我一樣，環境管理一直是 conda 黨，也不必遷就 venv：

conda create -n deeptutor python=3.11
conda activate deeptutor
python -m pip install --upgrade pip
# ...然后继续 `pip install -e .` 和 `npm ci`

建一個獨立的 conda 環境指定 Python 3.11，之後步驟完全一樣。

三、可選的安裝 extras

pyproject.toml 暴露了分層的可選元件（extras），要什麼裝什麼：

pip install -e ".[dev]"             # 测试 / lint 工具
pip install -e ".[partners]"        # 全部 Partner channel SDK（含 wecom-aibot-sdk）
pip install -e ".[matrix]"          # 不带 E2EE / libolm 的 Matrix channel
pip install -e ".[matrix-e2e]"      # 带 E2EE 的 Matrix；需要 libolm
pip install -e ".[math-animator]"   # Manim 插件；需要 LaTeX / ffmpeg / 系统库

也可以組合著裝：pip install -e ".[dev,partners,math-animator]"。

遠端 MCP（模型上下文協定）使用者端已包含在完整版和 CLI-only 的 core 安裝中，不需要 partners extra。

全集如下。其中七個 extra 有 requirements/*.txt 鏡像供 Docker/CI 建置使用，其餘直接從 pyproject.toml extras 安裝：

Extra 用途 Requirements 鏡像
cli 相容性 extra —— CLI 依賴，預設安裝已包含 requirements/cli.txt
server 相容性 extra —— FastAPI server 依賴，預設安裝已包含 requirements/server.txt
partners 全部內建 Partner channel SDK（ wecom-aibot-sdk 、 qq-botpy 、 slack-sdk 、 lark-oapi 、 python-telegram-bot 、 dingtalk-stream 等） requirements/partners.txt
tutorbot partners 的相容別名，保留一個版本週期 —
matrix Matrix（Element）channel，非 E2EE —— 不需要 libolm requirements/matrix.txt
matrix-e2e Matrix E2EE 附加包 —— 需要系統級 libolm 庫 requirements/matrix-e2e.txt
math-animator Manim 外掛 —— 需要 LaTeX、pkg-config、cairo、cmake、ffmpeg requirements/math-animator.txt
graphrag GraphRAG 檢索引擎——知識圖譜索引，LLM 開銷大；支援 Python 3.11–3.13 ——

部分 extras 需要的系統依賴

四、前端依賴調整

新增或升級前端依賴時：

cd web
npm install --legacy-peer-deps
# 同时提交 web/package.json 和 web/package-lock.json

改動要連 package.json 和 package-lock.json 一起提交，別人拉下來才能復現。

五、Dev server 故障排查

dev server 卡住：如果 deeptutor start --dev 報告已有前端但實際無回應，先停掉它列印出的 PID。如果根本沒有 Next.js 處理程序在跑，那是 lock 檔案過期了，刪掉重試：

rm -f web/.next/dev/lock web/.next/lock
deeptutor start --dev

六、熱重載

後端支援 --reload。在兩個獨立終端機裡分別啟後端和前端，開發體驗最好：

# 终端 A —— 带热重载的后端
python -m uvicorn deeptutor.api.main:app \
  --host 0.0.0.0 --port 8001 \
  --reload --reload-exclude "web/*" --reload-exclude "data/*"

# 终端 B —— 前端 dev server
cd web && npm run dev -- -p 3782

終端機 A 起後端並監聽 8001 連接埠，改動時自動重載；終端機 B 起前端開發伺服器，固定在 3782 連接埠。

這麼配完，改一行程式碼儲存即生效，前後端各自熱更新，寫起來爽歪歪。

七、升級

git pull
pip install -e . --upgrade
cd web && npm ci --legacy-peer-deps

如果某次發布動了設定 schema，再跑一次 deeptutor init 把新增欄位補上。已有設定會保留。

設定 → 關於 會把當前環境識別為原始碼 checkout 並顯示 Git revision，但不會替你 pull、merge 或覆蓋工作樹。原始碼安裝需要顯式使用 Git 更新，讓本機分支和未提交修改始終由你掌控。

八、常見錯誤

error: Microsoft Visual C++ 14.0 is required （Windows）

部分 Python 依賴會編譯 C 擴充。裝 Build Tools for Visual Studio，勾選 “Desktop development with C++“。

找不到 libolm （裝了 matrix-e2e 時）

brew install libolm                   # macOS
sudo apt install libolm-dev           # Debian / Ubuntu
pip install -e ".[matrix-e2e]" --force-reinstall

npm ci 慢或逾時

npm config set fetch-timeout 600000
cd web && npm ci --legacy-peer-deps

把 npm 的網路逾時調大到 600 秒再重試即可。

後端 --reload 每次儲存都瘋狂重新啟動

--reload-exclude 漏了。用下面命令重新啟動：

python -m uvicorn deeptutor.api.main:app \
  --host 0.0.0.0 --port 8001 \
  --reload --reload-exclude "web/*" --reload-exclude "data/*"

更多修復方法：故障排查。
