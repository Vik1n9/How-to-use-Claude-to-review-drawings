01 · Repo · 建立倉庫

GitHub 註冊與創建倉庫

GitHub 是放程式碼與網頁的雲端倉庫。一個倉庫（repository）就是「一個專案的家」，這份指南合集就住在裡面。

1. 註冊帳號

到 github.com 用 Email 註冊、設定使用者名稱（會出現在網址裡，例如本專案的 Vik1n9）、驗證信箱。

2. 建立新倉庫

右上角「＋ → New repository」，填名稱（One-Page-Beginners-Guide）、選 Public（公開才能用 Pages 展示）、勾選「Add a README file」。

README 是倉庫首頁說明文件；之後每新增一份指南，就更新它的索引。

3. 把網頁放進去

可用網頁介面「Add file → Upload」，或用指令。本次是用指令完成（見第 5 步）。一個 .html 檔就是一份可獨立開啟的指南。

02 · Plan · 發想與計畫

先想清楚、先寫計畫，確認後才動工。

這是整個流程最關鍵的紀律：不要一開口就叫 AI 寫程式。先讓它讀懂需求、盤點現況，把「要做什麼、怎麼做」寫成計畫，等你點頭再執行，能省下大量來回。

A — 給材料、講對象

把草稿丟給 AI，並說清楚讀者是誰（「熟悉台股、第一次接觸美股的社會人士」）。對象決定了用字深淺與內容取捨。

B — 讓 AI 進入「計畫模式」

請 AI 先探索現況、提出做法而不要急著動手。它會把方案寫成一份計畫，並在關鍵分岔點反問你。

本次的分岔提問：要 PPTX 還是互動網頁？投資組合要不要寫具體標的？要不要順便啟用線上展示？

C — 看過計畫，按下確認

計畫寫成文件後，你逐項確認或修改，AI 才開始實作。中途要追加要求（例如「第三方工具要附出處連結」）也是在這個關卡補上。

一句話心法
「描述意圖，不是下指令。」你負責定義想要什麼、給誰看、底線在哪；AI 負責把它變成可執行的計畫與程式。計畫這一關省下來的，是後面十倍的返工。

04 · Iterate · 溝通與修正

如何和 AI 來回修正

第一版不會完美。重點是建立一個可驗證的循環：你描述問題，AI 改，並用工具實際打開來看，確認真的修好，而不是「看起來像修好」。

修正循環：你描述需求 → AI 實作 → 截圖／驗證 → 抓問題 → 修正

案例 1 — 抓到一個真實的 bug：顏色不會切換

「綠漲紅跌 ↔ 紅漲綠跌」的切換鈕點了沒反應。AI 用預覽面板讀取網頁的實際計算樣式，發現少寫了一段 CSS 變數覆寫規則，補上後綠／紅就正確互換了。點下面切換看差在哪：

:root{
  --rise: var(--up);   /* 綠 */
  --fall: var(--down); /* 紅 */
}
/* 切換到台股時，沒有任何規則改寫 --rise/--fall */
/* → 顏色永遠不變，按鈕像壞掉 */
✕ 缺少依市場切換的覆寫，顏色不會翻轉
:root{ --rise: var(--up); --fall: var(--down); }
#colorDemo[data-market="us"]{ --rise:var(--up);   --fall:var(--down); }
#colorDemo[data-market="tw"]{ --rise:var(--down); --fall:var(--up);   }
/* 切到台股 → 漲變紅、跌變綠，正確互換 */
✓ 補上兩行覆寫，切換立即生效

案例 2 — 一句話就能調整內容

「下方給講者的備忘可以去除」，AI 直接刪掉那個區塊，並重新載入預覽確認頁尾沒有留下空白。簡短、明確的指令最有效。

案例 3 — 換格式時，連「會出包的細節」一起顧

「整份匯出成 PDF」。網頁轉 PDF 常見三個雷：深色背景變白、互動問答收合後看不到答案、靠捲動才出現的圖表沒被畫出來。AI 加上列印樣式（強制印背景、自動展開所有問答、補滿圖表），再用 PyMuPDF 逐頁檢查 13 頁都正確。

溝通三個訣竅
① 具體：說「頁尾備忘移除」比「再簡化一點」好下手。② 要求驗證：請 AI 截圖或實測，不要只憑想像。③ 分批：一次一個明確改動，容易確認、容易回退。
05 · Ship · 推送與展示

推送到 GitHub，並用 Pages 展示成線上網址。

檔案做好後，把它推上倉庫，再開啟 GitHub Pages，任何人就能用網址直接打開，不必下載檔案。

① 複製倉庫到本機

② 加入檔案、記錄變更、推上 main

commit 是「為這次變更留一筆紀錄」，push 是「把紀錄上傳到雲端」。本次依需求直接推上 main 分支。

③ 啟用 GitHub Pages（取得線上網址）

06 · Done · 完成

六步走完，一份指南就上線了。

整個流程收斂成五個可勾選的節點，每一個都對應前面一章。

  • 建立 GitHub 帳號與公開倉庫，放入 README
  • 讓 AI 先寫計畫、在分岔點提問，確認後才動工
  • 清楚知道調用了哪些技能與外掛，第三方都附出處
  • 用「描述 → 實作 → 驗證 → 修正」循環來回打磨
  • push 到 main、啟用 Pages，取得可分享的網址
